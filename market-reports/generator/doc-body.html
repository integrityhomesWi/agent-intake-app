03Dated URLs

Do not link to a dated report URL from the permanent report.

26 of the 28 dated URLs are redirect stubs that bounce the visitor straight back to the permanent report. A reader clicks "January 2026" and lands where they started.

They carry a per-month heading in the markup, so they look like real archive pages if you only read the source. They are not. The page redirects before it renders. Checking this properly means loading the URL in a browser, not fetching the HTML.

WhatCountDetail
Redirect stubs26location.replace() to the city's permanent report
Real archive pages2Waunakee April 2026, Sun Prairie January 2026. No redirect.
Deleted3The Madison ones. Also had no redirect.

The pattern

Redirect installed, the page survives. No redirect, and it is either deleted or still standing as real content. When a dated report is retired, install the redirect at the same time. That is what separated the 26 that lived from the 3 that were removed.

The redirects themselves are doing useful work consolidating authority into the permanent pages. Leave them. Just never point anything at them.

04Schema rules

Every page stands on its own

Google merges JSON-LD by @id within one page. It does not resolve an @id across pages. It reads each URL from scratch. So a bare reference to a node defined only on the home page points at nothing, and because publisher is required on an Article, that page ends up with no publisher at all.

This is what was wrong with all six city pages: four dangling references each, zero identity nodes defined.

The three stubs every page needs

#org       Organization + RealEstateAgent
           name, url, logo, telephone

#john      Person
           name, jobTitle, url, worksFor → #org

#website   WebSite
           url, name, publisher → #org

The IDs must match the home page exactly

CorrectWrong
#org#organization
#john#johnreuter
#websitematched already

The shared ID is what consolidates the entity across pages over time. A mismatched ID does not fail loudly, it quietly builds a second, competing entity.

Before publishing any page

Confirm every @id reference in the graph points at a node defined in that same graph. If it does not, the reference resolves to nothing.

05Writing rules

No placeholders

A page states a fact or it says nothing. There is no third option.

If a figure cannot be confirmed, the section that would have carried it does not get rendered. Never write a sentence explaining the gap.

Banned in any wording: could not be verified, not shown, unconfirmed, TBD, coming soon, to be determined, pending, awaiting data, check back, figure not available.

Missing data is a note to John, not page copy. The one exception is a real market fact that happens to be an absence: nothing available, no active listings in a bracket with zero inventory is data about the market, not an apology for missing data.

No em dashes

Use a colon in headings, a comma in prose, and n/a in an empty table cell. En dashes in numeric ranges are fine and expected: $300,000–$399,999.

The old chart-title spec required em dashes, which is where all 83 on the Madison page came from. That is fixed at the template.

No month or year in a title

This is the most expensive rule on the list, measured on this site across 16 months.
